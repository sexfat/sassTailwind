Tailwind CSS 完整講義

Tailwind CSS 是一套 Utility-First（工具優先） 的 CSS 框架。

它不給你「元件」，而是給你一堆小的、單一用途的 class（例如 flex、pt-4、text-center），讓你直接在 HTML 裡「組合」出樣式，幾乎不用自己寫 CSS。

1. 什麼是 Utility-First？

對應範例：01-basics.html　—　打開後對照這裡的寫法，看工具類組合出來的實際畫面。

傳統寫法：先想一個 class 名稱，再到 CSS 檔寫規則。

html
<div class="card">...</div>
css
.card {
  padding: 16px;
  border-radius: 8px;
  background: white;
  box-shadow: 0 2px 8px rgba(0,0,0,.1);
}

Tailwind 寫法：直接在 HTML 用工具類組合，不寫 CSS。

html
<div class="p-4 rounded-lg bg-white shadow-md">...</div>
  • p-4 = padding: 1rem
  • rounded-lg = border-radius: 0.5rem
  • bg-white = background: white
  • shadow-md = 一組預設陰影

為什麼這樣比較好？

  • 不用想 class 名字：不再糾結 .card-wrapper-inner 該叫什麼。
  • 不用切換檔案：改樣式就在 HTML 當下改，所見即所得。
  • 不會樣式衝突：沒有全域 CSS 互相覆蓋的問題。
  • 檔案不膨脹：Tailwind 只把「你用到的」class 打包進最終 CSS，沒用到的自動移除。
  • 設計一致性：間距、顏色、字級都來自預設的設計系統（4 8 16… 而非隨手 13px）。

常見疑慮：「HTML 會不會很醜很長？」

會比較長，但實務上：搭配元件框架（React/Vue）把重複的東西封裝成元件，或用 @apply 抽出常用組合即可。多數團隊實測後認為維護性利大於弊。

2. 與傳統 CSS / Bootstrap 的差異

傳統 CSS / SassBootstrapTailwind CSS
核心單位自訂 class現成元件（.btn、.card）工具類（.flex、.p-4）
客製彈性高（但要自己寫）低（改元件較麻煩）高（組合工具類）
長相是否雷同不會容易「一看就是 Bootstrap」不會
學習重點CSS 屬性記元件與 grid 系統記工具類命名規則
最終檔案大小看你怎麼寫較大（整包）很小（只留用到的）

一句話：Bootstrap 給你組好的家具，Tailwind 給你標準化的積木。

3. 安裝與環境（CDN / CLI / Vite）

本教材一律以 Tailwind CSS v4 教學與練習（官方最新版），所有範例與練習題都是 v4 寫法。

灰色的「v3 補充」區塊只是給需要維護舊專案的人參考，第一次學可以直接略過。

<!-- Tailwind v4 瀏覽器版 -->
<script src="https://unpkg.com/@tailwindcss/browser@4"></script>

本教材 examples/ 內的 HTML 都用這種方式，直接用瀏覽器打開就能看效果。

方法 C：Vite（正式專案推薦）

bash

4. 核心工具類速查

對應範例：01-basics.html　—　間距／尺寸／文字／顏色深淺四個區塊各附「動手改」提示，尺寸那區可以拖曳容器寬度看固定寬溢出。

工具類命名有固定規則，記住規則就能舉一反三。

間距（Spacing）— 最常用

數字是「間距刻度」，1 = 0.25rem = 4px，所以 p-4 = 16px。

Class意義
p-4 / px-4 / py-4 / pt-4padding（全 / 左右 / 上下 / 上）
m-4 / mx-auto / mt-2margin（mx-auto 水平置中）
gap-4flex/grid 的間距
space-x-4子元素之間的水平間距

尺寸（Sizing）

Class意義
w-full / w-1/2 / w-64寬 100% / 50% / 16rem
h-screen高度 = 視窗高
max-w-md最大寬度（sm/md/lg/xl…）
min-h-screen最小高度滿版

刻度沒有你要的數字時，用任意值（arbitrary value）：中括號直接寫 CSS 值，例如 w-[1200px]、h-[38px]、flex-[2]、top-[13px]。

固定寬 vs 最大寬

html
<!-- 寫死 1200px，視窗小於 1200px 時會溢出、產生水平捲軸 -->
<div class="w-[1200px]">...</div>

<!-- 比較好的做法：最大 1200px，小螢幕自動縮 -->
<div class="w-full max-w-[1200px] mx-auto">...</div>

w-[1200px] 是寫死寬度，不管視窗多小都佔 1200px；max-w-[1200px] 是上限，寬度由 w-full 決定，只是最多不超過 1200px。做版面容器幾乎都要後者，再配 mx-auto 水平置中、px-4 留左右安全邊界：

html
<div class="w-full max-w-[1200px] mx-auto px-4">...</div>

真的需要固定寬的情境（例如側欄、固定尺寸的卡片）就大方用 w-[1200px] 這類任意值，但記得在 flex 容器裡它預設仍會被壓縮，要保住寬度得加 shrink-0。

文字（Typography）

Class意義
text-sm / text-lg / text-2xl字級
font-bold / font-medium字重
text-center / text-right對齊
text-gray-600文字顏色（顏色-深淺）
leading-relaxed行高
tracking-wide字距

顏色（Color）

命名規則：屬性-顏色-深淺，深淺從 50（最淺）到 950（最深）。

html
<div class="bg-blue-500 text-white border-blue-700">...</div>
  • 背景：bg-red-500
  • 文字：text-green-600
  • 邊框：border-gray-300
  • 常見色系：slate gray red orange amber yellow green teal blue indigo purple pink

邊框與圓角、陰影

Class意義
border / border-2邊框粗細
rounded / rounded-lg / rounded-full圓角
shadow / shadow-md / shadow-xl陰影

顯示與定位

Class意義
block / inline-block / hiddendisplay
relative / absolute / fixedposition
top-0 / right-4 / inset-0定位偏移
z-10z-index
overflow-hidden / overflow-auto溢出處理

任意值（Arbitrary values）

預設刻度不夠用時，可用方括號寫任意值：

html
<div class="top-[117px] bg-[#1da1f2] w-[73%] text-[13px]">...</div>

5. Flexbox 與 Grid 佈局

對應範例：02-flex-grid.html　—　導覽列（Flex）、三欄卡片（Grid）、水平垂直置中三個可直接改的實作。

Flexbox

html
<div class="flex items-center justify-between gap-4">
  <div>左</div>
  <div>右</div>
</div>
Class意義
flexdisplay: flex
flex-col改為直向排列
items-center交叉軸置中（align-items）
justify-between主軸兩端對齊（justify-content）
justify-center主軸置中
flex-wrap允許換行
flex-1佔滿剩餘空間

用 Flex 做多欄：flex-1 vs w-1/2

同樣是「兩欄各半」，有兩種寫法，差別在誰決定寬度：

html
<!-- A. flex-1：平均分配「剩下的空間」-->
<div class="flex gap-4">
  <div class="flex-1">左</div>
  <div class="flex-1">右</div>
</div>

<!-- B. w-1/2：各自寫死父層寬度的 50% -->
<div class="flex gap-4">
  <div class="w-1/2">左</div>
  <div class="w-1/2">右</div>
</div>
flex-1w-1/2、w-1/3
寬度怎麼算剩餘空間平均分（gap 已先扣掉）父層寬度的固定比例
加了 gap沒問題，自動變窄比例失真（50% + 50% + gap > 100%，見下方說明）
內容很長時會一起被壓縮，欄寬仍相等撐不下去就不再收縮，內容溢出
適合等分欄位、自適應版面（最常用）需要精確比例、或搭配 flex-wrap 換行

w-1/2 + gap-4 到底會怎樣？ 加起來確實超過 100%，但實際結果取決於 flex-wrap：

  • 預設 flex（不換行）：flex 項目預設 flex-shrink: 1，兩欄會被等量壓縮成 calc(50% - 8px)。不會爆版，但也不再是真正的 50%——想要精確比例時就失真了。
  • 加 flex-wrap：一列放不下，第二欄整個換到下一行，變成上下各一欄。
  • 加 shrink-0（或內容有 min-width 撐著，例如長單字、whitespace-nowrap）：不能收縮又不能換行，這時才會真的溢出父層。

所以「爆版」只發生在第三種情況。真的要用比例又要間距，改用 w-[calc(50%-0.5rem)]，或直接用 flex-1／grid。

不等比例（左 2 右 1）：flex-[2] + flex-1，或 w-2/3 + w-1/3。

經典三欄 1 : 2 : 1（左右側欄 + 中間主內容）：flex-1 + flex-[2] + flex-1，或 w-1/4 + w-1/2 + w-1/4（後者不要加 gap，改用內距）。

手機一欄、桌機多欄：flex flex-col md:flex-row。

Grid

html
<div class="grid grid-cols-3 gap-4">
  <div>1</div><div>2</div><div>3</div>
</div>
Class意義
griddisplay: grid
grid-cols-33 欄
col-span-2跨 2 欄
gap-4格線間距

經典置中（水平垂直都置中）：

html
<div class="flex items-center justify-center h-screen">
  <div>置中內容</div>
</div>

6. 響應式設計 RWD（斷點）

對應範例：03-responsive-state.html　—　打開後拉寬／縮窄視窗，觀察 1 欄 → 2 欄 → 4 欄的切換點。

Tailwind 是 Mobile First：沒加前綴的樣式是手機版，加斷點前綴才是「該尺寸(含)以上」套用。

前綴生效寬度對應裝置
（無）全部手機
sm:≥ 640px大手機 / 直立平板
md:≥ 768px平板
lg:≥ 1024px筆電
xl:≥ 1280px桌機
2xl:≥ 1536px大桌機

範例：手機一欄、平板兩欄、桌機四欄。

html
<div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 gap-4">
  ...
</div>

常見錯誤：想在「手機」套樣式卻寫 sm:。記住——手機版不用前綴，sm: 是 640px 以上。

7. 狀態變體：hover / focus / group / peer

對應範例：03-responsive-state.html（hover / focus / active 與 group-hover 區塊）、 05-component-card.html（整張卡片連動）。

用「變體前綴 :」在特定狀態套樣式。

html
<button class="bg-blue-500 hover:bg-blue-700 focus:ring-2 active:scale-95">
  按鈕
</button>

常用變體：hover: focus: active: disabled: focus-within: first: last: odd: even:

group：依「父層狀態」改變子元素

在父層加 group，子元素用 group-hover: 反應父層的 hover。

html
<a href="#" class="group block p-4 border">
  <h3 class="group-hover:text-blue-600">標題</h3>
  <p class="text-gray-500 group-hover:text-gray-700">滑到整張卡都會變色</p>
</a>

peer：依「兄弟元素狀態」改變

常用於表單：input 有 peer，後面的元素用 peer-focus:、peer-invalid: 反應。

html
<input type="email" class="peer border" />
<p class="hidden peer-invalid:block text-red-500">Email 格式錯誤</p>

8. 深色模式 Dark Mode

對應範例：04-darkmode-theme.html　—　右上角按鈕可手動切換深／淺色，切完重整還會記得；檔案裡有 @custom-variant dark 與切換 JS 的完整寫法，「切換的 JS」那一區可以看到目前是手動選的還是跟隨系統。

用 dark: 前綴指定深色模式下的樣式。

html
<div class="bg-white text-gray-900 dark:bg-gray-800 dark:text-white">
  自動或手動切換深淺色
</div>
  • 預設：跟隨作業系統設定（prefers-color-scheme）。
  • 手動切換：在 <html> 加/移除 class="dark"（需設定 selector 策略），用 JS 切換：
js
document.documentElement.classList.toggle('dark');

設定手動切換策略：在 CSS 加 @custom-variant dark (&:where(.dark, .dark *));。

v3 補充

v3 是在 tailwind.config.js 設 darkMode: 'class'。

切換的 JS 完整寫法

上面那行一按就能切，但重新整理後就忘了。實務上要做到三件事：記住使用者的選擇、沒選過時跟隨系統、重整時不要閃一下白底。

第一段放在 <head>，在畫面繪製前就決定好要不要加 dark：

html
<!-- 放在 <head> 裡，越早越好，避免重整時先閃白底再變深色 -->
<script>
  const saved = localStorage.getItem('theme');
  const prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
  if (saved === 'dark' || (!saved && prefersDark)) {
    document.documentElement.classList.add('dark');
  }
</script>

第二段是按鈕本身，切換時順手把選擇存起來：

html
<button id="theme-toggle" class="px-4 py-2 rounded-lg bg-gray-200 dark:bg-gray-700">
  切換深／淺色
</button>

<script>
  document.getElementById('theme-toggle').addEventListener('click', () => {
    const isDark = document.documentElement.classList.toggle('dark');
    localStorage.setItem('theme', isDark ? 'dark' : 'light');
  });
</script>

重點整理：

做的事為什麼
classList.toggle('dark') 加在 documentElementdark: 是靠 <html class="dark"> 生效，不能加在 <body>
localStorage 存 'dark' / 'light'記住選擇，重整、換頁都還在
沒存過才看 prefers-color-scheme使用者手動選過就以他的選擇為準
判斷的 script 放 <head> 而非 </body> 前放太後面會先畫出淺色再變深色，出現俗稱的 FOUC 閃爍

想讓使用者「切回跟隨系統」，就把記錄清掉：localStorage.removeItem('theme')。

頁面在「使用者沒手動選過」的狀態下，可以再監聽系統主題變化即時跟著換：

js
window.matchMedia('(prefers-color-scheme: dark)').addEventListener('change', (e) => {
  if (localStorage.getItem('theme')) return;   // 手動選過就不要蓋掉
  document.documentElement.classList.toggle('dark', e.matches);
});

9. 自訂主題（@theme）

對應範例：04-darkmode-theme.html　—　@theme 定義 --color-brand 後直接使用 bg-brand，可自行再加一組顏色試試。

用 CSS 的 @theme

v4 把設定搬進 CSS，用 @theme 定義設計 token，會自動生成對應工具類。這就是本教材唯一使用的客製方式。

css
@import "tailwindcss";

@theme {
  --color-brand: #6366f1;        /* 產生 bg-brand / text-brand… */
  --color-brand-dark: #4f46e5;
  --font-display: 'Noto Sans TC', sans-serif;
  --spacing-18: 4.5rem;          /* 產生 p-18 / m-18… */
  --breakpoint-3xl: 1920px;      /* 新增 3xl: 斷點 */
}
html
<button class="bg-brand hover:bg-brand-dark font-display p-18">品牌按鈕</button>

v3 補充

v3 沒有 @theme，客製要寫在 tailwind.config.js：

js（v3 舊寫法，僅供參考）
module.exports = {
  content: ['./src/**/*.{html,js}'],
  theme: {
    extend: {
      colors: {
        brand: { DEFAULT: '#6366f1', dark: '#4f46e5' },
      },
      spacing: { 18: '4.5rem' },
    },
  },
};

v3 補充

config 裡的 extend 是「新增」；直接寫在 theme 底下會「覆蓋」預設值，所以通常用 extend。v4 的 @theme 預設就是「新增」，不會蓋掉內建刻度。

10. 重複樣式的處理：@apply 與元件抽取

對應範例：05-component-card.html　—　三張卡片的 class 完全重複，正好拿來練習把按鈕抽成 .btn-primary。

當同一組工具類到處重複（例如按鈕），有兩種做法：

做法 A：元件化（首選）

用 React/Vue 把它包成元件，class 只寫一次：

jsx
// React
function Button({ children }) {
  return <button className="px-4 py-2 rounded-lg bg-blue-500 text-white hover:bg-blue-600">{children}</button>;
}

Vue 3 的寫法

Vue 3 用單檔元件（SFC）+ <script setup>，內容用 <slot> 挖洞：

vue
<!-- components/BaseButton.vue -->
<template>
  <button class="px-4 py-2 rounded-lg font-semibold transition bg-blue-500 text-white hover:bg-blue-600">
    <slot />
  </button>
</template>
vue
<BaseButton>送出</BaseButton>

要支援多種樣式（primary / danger / ghost），用一張對照表把 variant 對到完整的 class 字串：

vue
<!-- components/BaseButton.vue -->
<script setup>
defineProps({
  variant: { type: String, default: 'primary' },
})

// 每個 value 都是「完整寫出來」的 class 字串，Tailwind 才掃得到
const variants = {
  primary: 'bg-blue-500 text-white hover:bg-blue-600',
  danger: 'bg-red-500 text-white hover:bg-red-600',
  ghost: 'bg-transparent text-blue-600 hover:bg-blue-50',
}
</script>

<template>
  <button :class="['px-4 py-2 rounded-lg font-semibold transition', variants[variant]]">
    <slot />
  </button>
</template>
vue
<BaseButton>送出</BaseButton>
<BaseButton variant="danger">刪除</BaseButton>
<BaseButton variant="ghost" class="w-full">取消</BaseButton>

搭配 Vue 時有兩件事要注意：

1. class 名稱不能用字串拼接。 Tailwind 是掃描原始碼的「純文字」來決定要產生哪些 CSS，拼出來的字串在檔案裡根本不存在：

vue
<!-- 不行：檔案裡找不到 bg-blue-500 這串字，不會產生 CSS -->
<button :class="`bg-${color}-500`">

<!-- 可以：完整 class 寫在對照表裡 -->
<button :class="colors[color]">

2. 外面傳的 class 會自動合併到根元素。 這是 Vue 的 attribute fallthrough，不用自己宣告 class prop，上面 <BaseButton class="w-full"> 的 w-full 就會加到 <button> 上。兩個提醒：

  • 元件有多個根節點時 fallthrough 會失效，要自己 v-bind="$attrs" 指定接在哪一個節點。
  • 內外同性質的 class 衝突時（外面 px-8、裡面 px-4），誰贏是看 utility 在產生的 CSS 裡的順序，不是看你寫的順序，結果不一定如預期。需要可靠覆蓋就裝 tailwind-merge，搭配 defineOptions({ inheritAttrs: false }) 自己合併：twMerge('px-4 py-2 ...', useAttrs().class)，讓外面傳的確實蓋掉裡面的。

做法 B：@apply 抽出自訂 class

在 CSS 用 @apply 把工具類組合成語意化 class：

css
@import "tailwindcss";

@layer components {
  .btn {
    @apply px-4 py-2 rounded-lg font-semibold transition;
  }
  .btn-primary {
    /* 直接列出 utility，不要用 @apply 去串接另一個自訂類 .btn */
    @apply px-4 py-2 rounded-lg font-semibold transition
           bg-blue-500 text-white hover:bg-blue-600;
  }
}
html
<button class="btn-primary">送出</button>

兩個提醒：

1. 別過度使用 @apply。官方建議 優先用元件抽取，@apply 只在少數真的重複、又無法元件化時使用（否則就退回傳統 CSS 的老問題了）。

2. @apply 請直接列 utility class，不要 @apply btn ... 去串接「另一個自訂類」——v4 中這種串接不保證有效，把 utility 直接寫出來最穩妥。

11. 推薦工具與最佳實踐

必裝工具

  • Tailwind CSS IntelliSense（VS Code 擴充，擴充 ID bradlc.vscode-tailwindcss）：class 自動補全、hover 顯示對應 CSS、顏色預覽、錯誤 class 提示。強烈建議必裝。
  • Prettier + prettier-plugin-tailwindcss：自動把 class 依官方順序排序，維持整潔。
  • 官方 Playground（play.tailwindcss.com）：線上即時試玩、看編譯結果。

安裝 IntelliSense：VS Code 左側 Extensions（Cmd/Ctrl + Shift + X）搜尋「Tailwind CSS IntelliSense」，或用命令列：

bash
code --install-extension bradlc.vscode-tailwindcss

用 Play CDN 的練習檔（本教材的 examples/、practice/）補全可能不會啟動——擴充是靠專案裡的 Tailwind 設定檔判斷要不要啟用。在專案根目錄放一個只有一行 @import "tailwindcss"; 的 tailwind.css（v4 寫法）即可喚醒它，這個檔案不影響 Play CDN 的執行。

再加上這段 VS Code 設定，讓補全在 class="…" 字串內也會跳出來：

json（.vscode/settings.json）
{
  "tailwindCSS.includeLanguages": { "html": "html" },
  "tailwindCSS.emmetCompletions": true,
  "editor.quickSuggestions": { "strings": true },

  // VS Code 內建 CSS 檢查不認識 v4 的 @theme / @utility / @custom-variant，
  // 會出現 "Unknown at rule" 黃色警告，關掉即可（不影響編譯）
  "css.lint.unknownAtRules": "ignore",
  "scss.lint.unknownAtRules": "ignore"
}

常見困擾：在 CSS 或 <style type="text/tailwindcss"> 裡寫 @theme、@apply、@utility 時，編輯器出現黃色波浪線「Unknown at rule @theme」。

那是 VS Code 內建的 CSS 檢查器不認得 Tailwind 的自訂語法，程式碼本身沒有錯、也能正常編譯。加上上面那兩行 unknownAtRules 設定就不會再跳警告。

最佳實踐

  1. 善用設計刻度：優先用 p-4、text-lg 這種刻度，少用 p-[13px] 任意值，維持一致性。
  2. Mobile First：先寫手機版（無前綴），再往上加 md:、lg:。
  3. 重複就抽元件，而不是狂複製 class。
  4. class 排序交給 Prettier，不用手動整理。
  5. 不確定 class 名稱：靠 IntelliSense 或查官方文件，不要硬背全部。

重點速記

  • Utility-First：在 HTML 組合小工具類，不寫 CSS。
